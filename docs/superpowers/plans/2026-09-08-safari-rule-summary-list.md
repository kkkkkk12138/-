# Safari 规则摘要列表实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Safari popup 在已有规则时完整展示摘要列表，并支持单行原地编辑、待应用空态和成功应用后保持列表可见。

**Architecture:** 保留 `mountPopup` 的存储与消息职责，将 `expanded` 状态替换为 `editingRuleId` 和 `hasPendingChanges`。渲染层按规则 ID选择摘要行或编辑行；空规则集合根据是否存在待应用删除区分初始空态和待应用空态。

**Tech Stack:** TypeScript、DOM API、Vitest、JSDOM、CSS、WebExtension API、Xcode Safari Web Extension。

  const popup = await mountPopup(document.getElementById('app')!);
  popup.addRule();
  const ruleId = document.querySelector<HTMLElement>('[data-rule-row]')!.dataset.id!;
  popup.updateRule(ruleId, 'source', '沈清辞');
  popup.updateRule(ruleId, 'target', '林惊鹤');

  await popup.apply();

  expect(document.querySelector('[data-rule-summary]')).not.toBeNull();
  expect(document.querySelector('[data-role="open-editor"]')).toBeNull();

- [ ] **Step 3: 实现状态转换**

实现以下规则：

```ts
function addRule(): void {
  const rule = createEmptyRule();
  state.rules = [...state.rules, rule];
  state.editingRuleId = rule.id;
  state.hasPendingChanges = true;
  state.errorMessage = '';
  render();
}
```

删除不再自动补空规则；删除最后一条后保留 footer，并由 `apply()` 发送 `DISABLE_PAGE`。成功应用后设置 `editingRuleId = null`、`hasPendingChanges = false`，有规则则渲染摘要，无规则则渲染初始空态。失败时不修改编辑 ID和内存规则。
