# Safari 规则生效与极简弹窗设计

## 目标

修复 Safari 中“规则已保存但当前网页没有替换”的问题，并将扩展弹窗收敛为默认只显示“添加规则”按钮的轻量交互。

本次不增加别名、云同步、账号、站点规则或独立阅读器。

## 问题根因

当前 popup 能保存规则，但消息层存在两处 Safari 特判：

- `sendTabMessage()` 在浏览器类型为 Safari 时直接返回，不向内容脚本发送消息。
- `apply()` 和 `setEnabled()` 在 Safari 中提前结束，将页面状态强制设为未启用。

因此 Safari 用户点击“立即生效”后，规则只进入本地存储，没有发送 `APPLY_RULES`，页面正文自然不会变化。

界面同时展示标题、教程、状态卡、规则计数、启用开关、规则说明和操作按钮，超出了阅读中临时换名所需的信息量。

## 默认交互

弹窗初始状态只显示一个主按钮：

```text
[ ＋ 添加规则 ]
```

不显示：

- 产品标题和副标题
- Safari 首发教程
- 权限说明卡片
- 有效规则数量
- 当前页状态
- 本页启用开关
- 规则说明

## 展开编辑器

点击“添加规则”后展开规则编辑器：

- 已保存规则按行显示
- 没有规则时显示一条空规则
- 每行包含“原名”“替换成”和删除操作
- 底部包含“再加一条”和“立即生效”

成功应用后编辑器自动收起，重新只显示“添加规则”。

删除全部规则并点击“立即生效”时：

- 清空本地规则
- 向当前页面发送 `DISABLE_PAGE`
- 内容脚本恢复原始文本
- 编辑器收起

## Safari 消息修复

消息发送不再依据浏览器品牌跳过。只要存在有效 `tabId`，就尝试通过 WebExtension `tabs.sendMessage()` 与当前页内容脚本通信。

正确流程：

1. 读取当前活动标签页
2. 读取内容脚本页面状态
3. 用户编辑并归一化规则
4. 保存规则到扩展本地存储
5. 有规则时发送 `APPLY_RULES`
6. 无规则时发送 `DISABLE_PAGE`
7. 内容脚本立即重算页面并管理 MutationObserver

Safari 和 Chromium 共用同一消息路径，只保留 API 调用形式的适配，不再做产品行为分叉。

## 权限错误

如果 Safari 尚未允许扩展访问当前网站，发送消息会失败。此时：

- 不丢失输入内容
- 不收起编辑器
- 在按钮上方显示一行简短提示
- 提示文案：`请允许扩展访问当前网站后重试`

不恢复教程卡片，也不在正常状态展示权限说明。

## 状态模型

popup 新增本地 UI 状态：

- `expanded`：是否展开规则编辑器，初始为 `false`
- `errorMessage`：最近一次应用错误，初始为空
- `isApplying`：防止重复提交

页面启用状态不再由用户通过开关维护：

- 成功发送有效规则即视为启用
- 清空规则并发送 `DISABLE_PAGE` 即视为停用

## 内容脚本

内容脚本继续使用现有换名引擎：

- `APPLY_RULES`：归一化规则、恢复并重算正文、启动动态内容监听
- `DISABLE_PAGE`：恢复原始文本并停止监听

如果现有 `stop()` 只停止监听但没有恢复原文，应补充恢复行为并增加回归测试。

## 测试

### popup

- 初始 DOM 只有“添加规则”入口，不渲染教程、状态卡和启用开关
- 点击“添加规则”后显示规则编辑器
- Safari 环境也向当前标签页发送 `APPLY_RULES`
- 成功应用后编辑器收起
- 发送失败时保留编辑器和输入内容，并显示简短权限提示
- 清空规则后发送 `DISABLE_PAGE`

### 内容脚本

- 收到 `APPLY_RULES` 后立即替换当前正文
- 更新规则后基于原始文本重新计算
- 收到 `DISABLE_PAGE` 后恢复原文
- 动态新增正文继续应用当前规则

### 构建

- 全量 Vitest 通过
- WebExtension 构建通过
- `apple:sync` 后 Safari 工程资源更新
- iOS Simulator 与 macOS 无签名构建通过

## 完成标准

- Safari 当前阅读页点击“立即生效”后正文立刻替换
- 扩展初始界面只显示“添加规则”
- 编辑、删除、应用规则仍可完成
- 权限错误不丢失用户输入
- 停用规则能恢复原文
- Chrome/Edge 兼容路径不回归
